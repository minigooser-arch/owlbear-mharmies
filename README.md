# Летопись: Армии

Расширение Owlbear Rodeo для стратегических карт: стороны, персональная видимость армий, маршруты, авторитетное движение ведущего, барьеры обзора и движения, столкновения и боевые группы.

Текущий релиз — `1.2.0`.

## Модель безопасности

Исходные изображения зарегистрированных армий скрываются, а каждому клиенту создаются только разрешённые local-клоны. Это защищает от случайного раскрытия на карте, но не является криптографической границей: metadata комнаты доступна клиентской среде Owlbear. Расширение рассчитано на честную игру.

## Требования

- Node.js 22.12 или новее (проверено на 24.18.0);
- npm;
- Owlbear Rodeo;
- статический HTTPS-хостинг для production-сборки.

## Локальный запуск

```powershell
npm.cmd install
npm.cmd run dev
```

В настройках Owlbear Rodeo добавьте manifest URL:

```text
http://localhost:5173/owlbear-mharmies/manifest.json
```

Production manifest URL:

```text
https://minigooser-arch.github.io/owlbear-mharmies/manifest.json
```

Если Vite выбрал другой порт, используйте адрес из его вывода. Окно разработки должно оставаться запущенным.

## Production-сборка

```powershell
npm.cmd run check
```

Опубликуйте содержимое `dist/` как корень статического HTTPS-сайта и добавьте в Owlbear URL `https://ваш-домен/manifest.json`. В сборку входят popover, постоянный background entrypoint, manifest и icon.

## Быстрый старт ведущего

1. Создайте стороны, добавьте участников и назначьте одного или нескольких лидеров. Права привязаны к внутреннему `Player.id`, а один игрок может состоять сразу в нескольких сторонах.
2. Для регистрации выделите ровно один Image-токен, выберите его сторону в разделе «Армии» и нажмите **Сделать армией**. Регистрировать и снимать регистрацию может только ведущий.
3. При необходимости задайте армии индивидуальные дальность, скорость и лимит маршрута.
4. Укажите отношения сторон. Столкновения возникают только между `ENEMY`.
5. Постройте маршруты инструментом расширения и запустите отдельные армии либо все сразу.
6. Управляйте возникшими боями и меняйте их названия на вкладке «Бои».

## Маршруты и движение

Каждая точка маршрута привязывается к центру клетки через Owlbear grid snap, а длина считается через `OBR.scene.grid.getDistance` для каждого сегмента. Лимит по умолчанию — 5 клеток. При перетаскивании дальше лимита зелёная линейка остаётся на самой дальней допустимой клетке. Ведущий может менять глобальный лимит и overrides армии. Снижение лимита не удаляет сохранённый маршрут.

- Только ведущий назначает лидеров и регистрирует армии.
- В списках игрок видит только армии сторон, участником которых является; ведущий видит все армии.
- Лидер может добавлять и удалять обычных участников своих сторон, а также планировать маршруты всех армий этих сторон.
- Лидер не может запускать, ставить на паузу, продолжать или останавливать движение — эти команды остаются у ведущего.
- Пока армия имеет статус `READY`, её запланированный маршрут видят только ведущий и лидеры стороны. После запуска (`MOVING`, `PAUSED` или `IN_BATTLE`) маршрут видят все участники этой стороны, но не чужие стороны.

Только выбранный GM-координатор записывает автоматическое движение и BattleGroup. При потере координатора движение приостанавливается без компенсации пропущенного времени. Local-интерполяция и reconciliation не создают пользовательские команды благодаря origin guard.

## Барьеры

Барьеры хранятся скрытыми Curve-источниками и отображаются local-overlays. Флаги `blocksMovement` и `blocksVision` независимы. Армия также может независимо игнорировать барьеры движения или обзора.

## Диагностика

Вкладка «Диагностика» содержит шесть live-проверок:

- получение выбранного source item;
- создание local item;
- наблюдение изменения local item;
- безопасное обновление и восстановление source item;
- работа background после закрытия popover;
- доступность контекстного меню local item.

Выполните их в реальной комнате. Результат context menu может быть `SDK_LIMITATION`; это не считается успешной проверкой.

## Известные ограничения

- Скрытие — визуальная модель честной игры, не серверная секретность.
- Live-room проверки нельзя заменить unit/integration-тестами; до запуска пользователем они отмечены `NOT_RUN`.
- Поддержка context menu для local items зависит от версии Owlbear SDK.
- `npm audit` сообщает moderate advisory в транзитивном `uuid@9` внутри `@owlbear-rodeo/sdk@3.1.0`. SDK использует `uuid.v4()` без уязвимого buffer API; официального совместимого исправления для зафиксированной версии SDK нет. High и critical advisories отсутствуют.
- При одновременной работе нескольких вкладок GM координатором становится подключение с лексикографически минимальным connection ID.
