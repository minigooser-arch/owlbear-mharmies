# Letopis Armies Design

## Назначение

`Letopis: Armies` — расширение Owlbear Rodeo для стратегической игры армиями. Оно даёт ведущему централизованное управление армиями, маршрутизацией, движением, барьерами и боями, а игрокам показывает только армии, доступные их стороне по правилам обнаружения.

## Границы первой версии

Первая версия реализует полный объём из 14 задач исходного implementation plan:

- регистрацию изображений как армий и распределение по сторонам;
- независимое и взаимное обнаружение с дальностью в клетках;
- локальные клоны для персональной видимости без использования fog API;
- маршруты с лимитом 5 клеток по умолчанию;
- авторитетное движение под управлением активного GM-координатора;
- независимые барьеры движения и обзора с исключениями для отдельных армий;
- столкновения в движении и жизненный цикл BattleGroup;
- права GM, владельца армии и участника стороны;
- русскоязычный popover, контекстные действия и инструменты карты;
- диагностику Owlbear SDK, интеграционный сценарий на четырёх клиентах и production-сборку.

Вне области версии 1: криптографическая защита скрытых данных, серверный backend, собственная синхронизация вне Owlbear и автоматическое подтверждение live-room проверок без реального запуска в комнате.

## Архитектура

Система делится на три уровня.

1. Чистые TypeScript-модули содержат схемы, валидацию, геометрию, расчёт маршрутов, обнаружение, движение, столкновения и операции над боевыми группами. Они не импортируют Owlbear SDK и тестируются детерминированно.
2. Прикладной слой работает через узкий SDK-адаптер. Он хранит metadata, обрабатывает команды, выбирает GM-координатора, согласует локальные клоны и overlays, управляет подписками и таймерами.
3. React popover строит уже отфильтрованную по роли view model и отправляет типизированные команды. UI не получает скрытые армии в карточках, фильтрах или счётчиках.

Постоянный background entrypoint владеет подписками и координацией. Только активный GM-координатор записывает автоматические перемещения и состояние BattleGroup. При потере координатора движущиеся армии переходят в `PAUSED` без компенсации пропущенного времени.

## Модель данных и авторитетность

Все данные расширения используют namespace `com.letopis.army-control`. Scene metadata хранит стороны, симметричные отношения, глобальные настройки, BattleGroup и lease координатора. Metadata изображения хранит состояние армии; metadata скрытой Curve — состояние барьера.

Схемы версионируются. Значения старых версий мигрируют последовательно, повреждённые значения дают контролируемую ошибку, а неизвестная будущая версия переводит интерфейс в read-only и никогда не перезаписывается. Записи используют revision check, чтобы устаревшая команда завершалась конфликтом.

Broadcast-команды содержат request ID, player ID, connection ID и ожидаемую revision. Обработчик сверяет connection ID события с payload и выполняет все изменения через один exhaustive dispatcher.

## Видимость

Исходные изображения зарегистрированных армий глобально скрыты. Для каждого клиента расширение создаёт локальные Image-клоны только для разрешённых источников. Свои армии видны стороне всегда; чужие появляются по графу обнаружения или через участие в доступной BattleGroup. GM видит все армии.

Точная дальность измеряется только через `OBR.scene.grid.getDistance`. Пиксельная геометрия используется для broad phase и пересечений отрезков. В независимом режиме обнаружение одностороннее. Во взаимном режиме ответная видимость добавляется только реально участвующей стороне и не раскрывает цель третьим сторонам.

Скрытие является моделью честной игры, а не границей безопасности: metadata Owlbear нельзя считать секретным серверным хранилищем.

## Маршруты, движение и барьеры

Маршрут — упорядоченный список точек. Его длина равна сумме точных grid-distance сегментов. Глобальный лимит по умолчанию равен 5 клеткам и может переопределяться для армии. Уменьшение лимита не удаляет существующий длинный маршрут, но запрещает его запуск до исправления.

Активный координатор двигает армии по delta-time, обрабатывает несколько точек за тик без перелёта и дробит нормальные интервалы максимум до 0,2 секунды. Разрыв больше 3 секунд означает `COORDINATOR_GAP` и паузу. Локальная интерполяция сглаживает отображение, не создавая авторитетных записей.

Барьеры — скрытые заблокированные Curve-источники. Проверки движения и обзора независимы, как и исключения армии. При пересечении барьера движения армия останавливается до линии, сохраняет остаток маршрута и получает причину паузы `BARRIER`.

## Столкновения и бои

Столкновения учитываются только между сторонами с отношением `ENEMY`. Swept AABB отбирает кандидатов, после чего адаптивные точные измерения и бинарный поиск находят первый контакт между тиками. Порог пары — максимум collision range двух армий.

При контакте армии переходят в `IN_BATTLE`. Прямой контакт может присоединять подкрепления и объединять группы. Merge выбирает лексикографически минимальный существующий ID; новый ID создаётся через внедрённый UUID provider. Изменение отношений перестраивает компоненты BattleGroup атомарно. Освобождённые армии становятся `PAUSED`, а их маршруты сохраняются.

## UI и инструменты

Popover полностью русскоязычный и содержит разделы армий, сторон, отношений, движения, боёв, настроек и диагностики. Действия, которые удаляют или массово меняют состояние, требуют подтверждения. Доступность контролов определяется ролью и текущим статусом.

Инструмент маршрута показывает оставшееся расстояние, запрещённую точку и пересечение барьера; поддерживает мышь, `Backspace`, `Enter` и `Escape`. Инструмент барьеров доступен только GM. Маршруты, подписи, барьеры и previews рисуются локальными items и очищаются при закрытии сцены.

## Ошибки и восстановление

Пользователь получает русское уведомление для отказа в правах, конфликта revision, превышения маршрута, барьера, потери координатора и повреждённых данных. Отклонённое перетаскивание локального клона откатывается к последней авторитетной позиции.

Все подписки имеют явный unsubscribe и принадлежат lifecycle сцены. Runtime не допускает параллельных coordinator ticks. Reconciliation удаляет дубликаты клонов детерминированно и помечает собственные обновления origin guard, предотвращая циклы команд.

## Проверка качества

Чистая логика разрабатывается через TDD; SDK мокается только на прикладных границах. Обязательны unit-тесты каждого доменного модуля, тесты lifecycle и прав, UI-тесты на отсутствие утечки скрытых данных и интеграционный сценарий GM/A/B/C.

Финальная автоматическая проверка: typecheck, ESLint, Vitest и Vite production build. Шесть live SDK probes документируются отдельно и остаются `NOT_RUN`, пока пользователь не выполнит их в реальной комнате Owlbear Rodeo.

## Технологические ограничения

- TypeScript 6.0.3, React 19.2.7, Vite 8.1.4. TypeScript 7.0.2 из исходного плана заменён на 6.0.3, потому что `typescript-eslint` 8.63.0 поддерживает версии только ниже 6.1.0.
- `@owlbear-rodeo/sdk` 3.1.0.
- Vitest 4.1.10, Testing Library 16.3.2, jsdom 29.1.1.
- Node.js 22.12 или новее и npm.
- Строгий TypeScript с `noUncheckedIndexedAccess` и `exactOptionalPropertyTypes`.
- Весь пользовательский текст на русском, идентификаторы кода на английском.
