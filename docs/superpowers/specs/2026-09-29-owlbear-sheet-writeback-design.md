# Owlbear → Google Sheets writeback

## Цель

Сделать Google Sheets проекцией состояния глобальной карты: расчёты, проверки достаточности ЛР, изменение HP армий и порядок ходов остаются внутри Owlbear, а после успешного изменения состояния актуальные значения ЛР и HP отправляются в таблицу. Таблица не участвует в принятии игровых решений и не может отклонить команду, уже принятую Owlbear.

## Согласованный результат

- ЛР государства хранится и расходуется в `SceneState.demographics`.
- HP армии хранится в `SceneState.armies` и изменяется только валидными командами/ходом.
- После успешной фиксации команды в сцене создаётся идемпотентная запись синхронизации.
- Внешняя запись выполняется только координатором сцены, чтобы несколько клиентов Owlbear не писали одну операцию несколько раз.
- Временный сбой Google не откатывает игровой результат: запись остаётся в очереди и повторяется.
- Повторная доставка с тем же `eventId` не изменяет таблицу повторно.

## Внешний шлюз

Используется Google Apps Script Web App, развёрнутый от аккаунта владельца таблицы. Скрипт не является игровым сервером: он только принимает проверенный снимок изменений и выполняет атомарный upsert в Google Sheets.

В настройках сцены задаются:

```text
sheetWritebackUrl?: string
sheetWritebackToken?: string
```

Развёртывание Apps Script должно выполнять код от аккаунта владельца таблицы. Прямое редактирование файла остаётся ограничено разрешениями Google; доступ к Web App дополнительно закрывается токеном сцены. Токен находится в общей сцене Owlbear, поэтому это защита от случайных вызовов, а не криптографическая граница доверия. Команды всё равно разрешаются только существующей системой Owlbear.

### Контракт POST

```json
{
  "protocolVersion": 1,
  "eventId": "scene-id:revision",
  "sceneId": "scene-id",
  "revision": 123,
  "createdAt": "2026-09-29T15:00:00.000Z",
  "states": [
    { "stateId": "state-1", "country": "united_kingdom", "humanResource": 584, "humanResourceCapacity": 1843 }
  ],
  "armies": [
    {
      "armyId": "army-1", "stateId": "state-1", "country": "united_kingdom", "sideId": "side-1",
      "sideName": "Радикальная партия", "armyName": "Армия Лондона", "hp": 25, "maxHp": 40,
      "status": "READY", "updatedAt": "2026-09-29T15:00:00.000Z"
    }
  ]
}
```

Снимок содержит только затронутые государства и армии. Пустые массивы допустимы, но запрос без изменений не создаётся. Ответ шлюза: `{ "ok": true, "eventId": "scene-id:revision", "appliedStates": 1, "appliedArmies": 1 }`. Ошибки возвращают `ok: false` и стабильный код (`INVALID_TOKEN`, `INVALID_PAYLOAD`, `UNKNOWN_COUNTRY`, `SHEET_WRITE_FAILED`).

## Структура книги

### `backend`

Существующие колонки и формулы не переписываются. Apps Script находит строку по `country` (при наличии также проверяет `uuid`) и создаёт/использует отдельную колонку `human_resource` в тысячах человек. При каждом upsert обновляются только `human_resource` и служебные поля writeback, если они присутствуют. Население, GDP, коэффициенты и формулы остаются источником импорта/ручного управления и не меняются этим потоком.

### `armies`

Apps Script создаёт вкладку при первом запросе и гарантирует заголовок: `armyId | stateId | country | sideId | sideName | armyName | hp | maxHp | status | updatedAt | sceneId`.

Строка находится по стабильному `armyId`. При уничтожении армия не удаляется из таблицы: записываются `hp = 0`, `status = DESTROYED`. При добровольном расформировании используется `DISBANDED`. Это сохраняет соответствие между историей и токеном Owlbear.

## Поток данных

1. Клиент отправляет команду существующим `CommandGateway`.
2. Координатор выполняет авторизацию и `CommandProcessor`.
3. При отклонении команды таблица не вызывается.
4. При успешном commit вычисляется diff предыдущего и нового `CommandState`: изменённый `humanResource` добавляется в `states`; изменённый HP, созданная армия, уничтоженная армия или расформированная армия добавляются в `armies`; бесплатное лечение после хода и боевые потери попадают в этот же diff автоматически.
5. Diff получает `eventId = <sceneId>:<sceneRevision>` и сохраняется в устойчивой очереди writeback.
6. Координатор отправляет очередь последовательно. При успешном ответе запись удаляется; при сетевой/HTTP ошибке сохраняется с экспоненциальной задержкой.
7. После повторного открытия сцены очередь восстанавливается и продолжает отправку. Невалидное сопоставление страны не блокирует Owlbear: запись помечается ошибкой и показывается мастеру.

Очередь не должна повторять старые снимки после подтверждённого ответа. Для конфликтов используется правило «последний снимок побеждает» внутри одного `armyId` или `country`, но разные `eventId` сохраняются до подтверждения.

## Изменения в расширении

- `SceneSettings`: URL и токен writeback с обратной совместимостью.
- Новый чистый модуль diff/нормализации payload, не зависящий от Owlbear API.
- Новый transport/queue модуль с ограничением: только координатор делает POST, максимум один запрос одновременно.
- Хук writeback после успешного `persistCommandState`, а не внутри чистого командного процессора.
- GM-раздел настроек показывает URL, токен и состояние очереди (`ожидает`, `отправляется`, `ошибка`, `синхронизировано`), но не позволяет игрокам менять параметры.
- Диагностика содержит последнюю ошибку, количество ожидающих событий и время успешной отправки.

## Идемпотентность и сбои

- `eventId` уникален для версии сцены; повторный POST безопасен.
- Очередь ограничивает размер и схлопывает ещё не отправленные обновления одного `country`/`armyId`, не теряя самый свежий снимок.
- Ошибка записи в таблицу никогда не меняет уже принятый игровой результат и не показывает игроку ложное «команда не выполнена».
- При отсутствии URL writeback поток отключён, существующий импорт CSV продолжает работать.
- Если страна не имеет `backendCountry`, состояние армии/ЛР сохраняется локально и попадает в диагностическую ошибку до исправления сопоставления.

## Тестирование

- Чистый diff обнаруживает списание/коррекцию ЛР, создание, боевой урон, лечение, уничтожение и расформирование армии.
- Payload сохраняет единицы ЛР в тысячах и целочисленный HP.
- Очередь повторяет временные ошибки, удаляет событие после `ok: true` и не дублирует одинаковый `eventId`.
- Координатор отправляет, не-координатор не отправляет.
- Команда, отклонённая из-за недостатка ЛР или прав, не создаёт writeback.
- Старые сцены без настроек writeback мигрируют без изменения поведения.
- Apps Script тестируется отдельными контрактными тестами на upsert по `country`/`armyId`, создание вкладки и обработку повторного `eventId`.

## Ограничения

- Расширение не читает обратно текущие ЛР/HP из Sheets для игровых расчётов.
- OAuth Google в каждом клиенте не используется.
- Синхронизация отражает только изменения, зафиксированные в Owlbear; ручная правка таблицы будет перезаписана следующим writeback-снимком.
