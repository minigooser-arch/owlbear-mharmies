# PR #90 — предрелизная проверка и порядок слияния

**Кандидат:** 1.2.29. **Основа:** `main`. **Стратегия:** один squash-commit после ручного приёмочного теста; исходную ветку сохранить до проверки выпуска. **Слияние и публикация не выполнены.**

## Что подтверждено автоматически

- `npm ci`, `npm audit --audit-level=high --omit=dev`, проверка Apps Script, `npm run check` (TypeScript, ESLint, Vitest, production build + верификация `dist`).
- GitHub Actions `CI` и `Popover layout probe` должны иметь зелёный статус на **последнем SHA ветки**, не на одном из ранних коммитов.
- Сверить версию `package.json`, `package-lock.json`, `public/manifest.json`: везде 1.2.29; URL popover и background содержат параметр `v` с единым cache token. На GitHub Pages скрипт публикации заменяет его на короткий `GITHUB_SHA`.
- Сравнение с `main`: нет конфликтов и непредвиденных изменений в миграциях/формате хранения, разрешениях команд или правилах боя.

**Ограничение:** ни успешный Vitest, ни Chrome layout probe не доказывают корректность синхронизации настоящих подключений Owlbear. Предыдущие результаты в `docs/verification-results.md` относятся к другой дате и версии.

## Критерий GO / NO-GO

**GO**, только если все CI на финальном SHA зелёные, нет конфликтов с `main`, пункты ручной матрицы для критических игровых функций выполнены без новых ошибок, данные после повторного открытия совпали, и есть сравнение с 1.2.28. Непроверенные GM-арбитраж, приватность/разведка, сохранение маршрутов или целостность территорий означают **NO-GO**.

Остаточный риск: Owlbear scene metadata не предоставляет атомарный compare-and-swap для lease; проверки ревизии с повторным чтением уменьшают, но не устраняют предельную гонку между одновременно пишущими GM. Именно поэтому многоклиентская проверка обязательна.

## Публикация после GO

1. Проверить `main` и финальный SHA PR, убедиться, что не было новых коммитов со стороны других разработчиков.
2. Слить PR #90 **squash merge** (только после отдельного решения о выпуске).
3. GitHub Actions `Deploy GitHub Pages` запускается по `push` в `main`, выполняет `npm ci`, `npm audit`, `npm run check`, затем публикует `dist`.
4. Убедиться, что опубликованный `manifest.json` показывает 1.2.29 и содержит новую пару URL/токенов для popover и background. Проверить HTML и JS в обоих iframe; обновить кэш Owlbear.
5. Повторить smoke-тест на четырёх клиентах, посмотреть нагрузку и видимость; не менять живые игровые данные до подтверждения.
6. Внести реальные результаты и даты в `docs/verification-results.md`, не перезаписывая архив испытаний предыдущих версий.

## Откат

Если после публикации появилась регрессия, остановить действия GM на карте, сделать резервную копию сцены и **revert squash-commit** в `main`; GitHub Pages опубликует прежний код. При необходимости восстановить версию 1.2.28 и обновить cache-busting URL с новой сборкой. Не удалять или преобразовывать метаданные сцены автоматически: PR не предусматривает миграцию сохранений, но данные могли измениться в ходе игры. Сначала проверить целостность резервной копии.
